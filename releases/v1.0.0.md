# v1.0.0

- **日期**：2026-10-20
- **产品线**：abu-api-team
- **镜像**：`abu116/abu-api-team:v1.0.0`
- **递增类型**：MAJOR（对外版本叙事重开）

---

## Highlights

- 产品版本正式采用 SemVer，以 **v1.0.0** 作为对外起点（取代历史四段号如 `v0.4.0.2`）
- 控制台新增「更新日志」与登录后 What's New
- 自托管默认开启官方更新检查；有新版本时管理员可见提示（可关，**不会自动升级**）
- Telegram 支持单独推送发版说明（与日常系统公告同步分离）

---

## Operators

### 破坏性变更

- **版本号格式**：正式版本改为 `vMAJOR.MINOR.PATCH`（可带 `-alpha` / `-rc`）。历史四段号不再用于新正式发布。
- **主线镜像**：请使用 `abu116/abu-api-team`；`abu116/abu-api` 为非主推通道。

### 数据库迁移

本版主要为发版体系与产品呈现，**不单独附带**必跑的新 schema。若你的实例跨过较长时间未升级，请在切换流量前对**同一镜像**执行迁移工具（见下方步骤）；SQL 迁移版本与产品版本号解耦。

### 配置变更（镜像内可选）

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `UpdateCheckEnabled` | `true` | 自托管更新检查 |
| `UpdateCheckURL` | 空（官方默认） | 覆盖 feed；默认指向官方 `/api/release-notes/latest` |
| `TelegramChannelSyncReleasesEnabled` | `true` | 允许手动推送发版说明到频道 |

### 升级步骤（本仓库模板）

以 `standalone/` 为例（`cluster/` / `examples/*` 同理，改对应目录即可）：

```bash
cd abu-deploy/standalone   # 或 cluster / examples/mysql / examples/postgres
# 1. 备份 .env、数据卷与数据库
cp .env .env.bak.$(date +%Y%m%d)

# 2. 固定到本版镜像（推荐显式 tag，勿只靠 latest 碰运气）
export ABU_API_IMAGE=abu116/abu-api-team:v1.0.0
# 或在 .env 中设置：ABU_API_IMAGE=abu116/abu-api-team:v1.0.0

# 3. 拉取并滚动（单机可直接 up）
docker compose pull
docker compose up -d

# 4. 若部署使用 verify / 独立迁移：对同一镜像执行 abu-db-migrate up
#    （以你当前 compose 中的迁移约定为准）

# 5. 核对版本
curl -s http://127.0.0.1:8003/api/status | grep -o '"version":"[^"]*"'
# 期望："version":"v1.0.0"
```

集群请使用本仓库既有滚动方式，并保证迁移在切换流量前完成；**不要**执行数据库 down。

### 回滚边界

- 将 `ABU_API_IMAGE` 改回上一 tag 后 `docker compose up -d` 即可回滚应用
- **不**执行数据库 down
- 若曾执行过不兼容迁移，回滚前须确认旧镜像能否在新 schema 上运行
